# 鍵闘 KENTOU — 改良フェーズ設計

- 日付: 2026-09-03
- 前提: [初版設計](2026-09-03-kentou-design.md)
- 元になった調査: 公開版の実操作と、Grok 4.6（別モデル）へのセカンドオピニオン依頼

## 1. 実操作で見つかった不具合

| 症状 | 確認方法 |
|---|---|
| IMEがONだと完全に無反応 | `か` と `Process` キーを送出しても、お題・HP・演出が一切変化しない。ミス判定にもならず何も出ない |
| 打鍵0でも正確率100%と表示 | 無操作で敗北した画面が `KPM 0 / 正確率 100%` |
| 試合中に抜けられない | FIGHT中の `Escape` が無反応。誤って高難度を選ぶとリロードしかない |
| 無操作24.8秒で敗北（鬼） | 離席して戻るとHPが溶けている |
| 新しいお題の漢字が一瞬見えない | `slam` アニメが `opacity: 0` 始まりで、ローマ字ガイドは読めるのに漢字だけ空白の瞬間がある |
| `YOU LOSE` が横に溢れる | `K.O.` の4文字と同じ字送りで8文字を出していた |
| パーティクルが左上の小箱にしか出ない | `#fx` は canvas（置換要素）なので `inset: 0` だけでは伸びず 300×150 のままだった |

## 2. 設計上の穴

### コンボ自殺（優先度: 高）

お題の長さを**コンボ数だけ**で決めていた（`combo>=8` で長文、`>=4` で中文）。
ミスのペナルティはHP2点とコンボリセットのみ。つまり高難度で追い詰められたら
**わざと1文字ミスして短文帯に戻るのが生存最適**になっていた。
火力（コンボ倍率最大2.2倍）は失うので「速く勝つ」最適ではないが、
「負けない」最適としては成立してしまう。

### 互角帯が狭い

対戦の実体が「CPUのKPMを超えているか」の二値だった。超えていれば被弾はミスの
2点だけ、下回れば時間切れで溶ける。110はサンドバッグ、290はほぼQTE。

### 打撃が全部「中攻撃」に聞こえる

ヒットストップが70〜110msの一律。短文でも長文でも高コンボでも同じ1発だった。

### 試合の長さが腕前で数倍ぶれる

ダメージが速度に比例するのにHPは固定100。速い人は5お題、遅い人は17お題以上。

## 3. 実施した変更

### 第1波 — 壊れているものを直す

1. **IME検出** — `compositionstart` と、`Process`・非ASCIIキーの受信で
   「日本語入力（IME）がONです」の警告バナーを出す。黙って無視しない
2. **正確率の0打鍵表示** — 打鍵が1つも無い試合は `—` にする
3. **`ROUND 1` → `FIGHT!` の間** — `READY` フェーズを追加。この間タイマーは進まず、
   打鍵もミスにしない。最初のお題を読む時間を返す
4. **モード名の翻訳** — `見習い / 闘士 / 鬼` に体感の一言（「対戦らしい速度。まずここから」等）と
   KPM を併記し、おすすめを1つ光らせる
5. **FIGHT中の `Escape` で中断** — タイトルへ戻る。お題表示もクリアする
6. **自動ポーズ** — `visibilitychange` と `window.blur` で `PAUSED` に入る。
   復帰時は `wordElapsed` を戻して `FIGHT!` の間を挟むので、戻った瞬間に殴られない
7. **漢字の `slam` から `opacity: 0` を外す** — 拡大とぼかしだけにする
8. **ローマ字受理表** — タイトルの `<details>` に表を置く（JSなし）
9. **`#fx` に `width/height: 100%`** — canvas が実寸に伸びるようにする
10. **`YOU LOSE` / `PAUSE` の字送りを分離** — 長い文字列用に小さめの clamp を当てる

### 第2波 — ループを公平にする

11. **お題の長さをコンボから切り離す** — モードごとの許容ティア配列
    （見習い `[0,0,0,1]`、闘士 `[0,1,1,2]`、鬼 `[1,1,2,2]`）から引く。
    コンボ自殺の動機を消す
12. **ミスは「コンボ半減」** — `Math.floor(combo / 2)`。全断はパニック連打での即死を招くうえ、
    短文帯に戻る抜け道を安くしてしまう。HP罰は2点のまま上げない
    （上げると萎縮して練習ツールとして悪化する）
13. **打撃の階級化** — ダメージから弱／中／強／必殺を決め、ヒットストップ（45/80/135/210ms）・
    打撃音・ノックバック距離（CSS変数 `--kb`）・パーティクル量を段階分けする
14. **予兆モーション** — 残り1〜2文字でキャラが踏み込む。当たる前の溜めが打撃感の本体
15. **COUNTER** — 残り時間15%を切ってからの完打でダメージ1.4倍＋専用演出。
    残り時間ゲージも金色に変わって知らせる
16. **被弾側の演出強化** — ノックバック距離を大きく取り、ガードを割られる音（高域のノイズ→
    低域のスイープ）と `被弾` アナウンスを出す

### 第3波 — 練習ツールとしての価値

17. **修練モード** — 時間制限もCPUの攻撃もない4番目のモード。
    カテゴリ（技名／格ゲー用語／実況セリフ）と長さ（短文／中文／長文）を選べる。
    打鍵数・正確率・KPMを打つたびに更新する
18. **苦手キー分析** — キーごとにミス数と打鍵間隔を記録し、結果画面にワースト5を出す。
    ミスが皆無なら「打つのが遅いキー」に切り替える。
    3000ms以上の間隔（離席明け）は平均から除外する
19. **通算記録** — 前回比、自己ベスト、通算戦績。localStorage のみで外部送信なし。
    自己ベストは20打以上の試合だけを数える（1打で100%を記録させない）

## 4. 構造の変更

戦闘の数値計算を `src/battle.js` に切り出した。DOMも音も触らないので node から
検証できる。COUNTER の閾値到達はブラウザ操作では再現しにくい（開発時にペインが
非表示だと `requestAnimationFrame` が止まりゲーム時間が進まない）ため、
スクリーンショットではなくテストで固める判断をした。

打鍵記録と苦手キー分析は `src/stats.js` に分けた。localStorage は
プライベートウィンドウ等で例外を投げるので、読み書きは必ず例外を飲む。

これで DOM を持たないモジュールは `romaji.js` / `battle.js` / `stats.js` / `words.js` の
4つになり、それぞれにテストがある。`game.js` はそれらを画面と音に繋ぐだけになった。

## 5. 数値の再調整

階級の境界を実測してから決め直した。当初 `super` を34ダメージ以上としていたが、
実際にはコンボ4・12打で35ダメージに達し、中盤以降が全部「必殺」になっていた。
一戦で出る現実的な値（コンボ0〜8、5〜20打）を並べて、
`light < 14 / mid < 28 / heavy < 45 / super` に置き直した。
この「一戦で4階級が順に出る」性質は `battle.test.js` で固定している。

## 6. 採らなかった案

Grok の警告と自分の判断が一致した点を、明示的に却下として残す。

- **攻撃・ガード・必殺を別キーに割り当てる** — タイピングの認知を割る。
  必殺は自動発動（階級として現れる）に留める
- **1打ごとのヒットストップ強化・シェイク増量** — 今の密度が上限。
  足すと遅延に感じるし `prefers-reduced-motion` 以外の人も酔う
- **ミスのHPダメージ引き上げ** — コンボ半減で十分。上げるとパニック死が悪化する
- **対戦でのバックスペース解禁** — 文書編集になり、ミスの「空振り」が消える
- **CPUが並列で文字列を打つAI** — 視線がお題から離れる。制限時間を「発生」に
  見せる方が安い
- **キャラ選択・ステージ・音声素材** — ゼロ素材の強みを捨てる。ループの公平性が
  先である
- **本戦のラウンド制（2本先取）** — フィードバックまでの時間が延びる。
  ループが公平になってからで良い
- **モバイル仮想キーボード** — 中途半端に足すと「打てない対戦ゲーム」になる。
  断り文のままが正しい
- **オンラインランキング** — 改ざん前提の数字は信頼を削る。履歴はローカルで足りる

- リプレイ（打鍵タイムスタンプの再生）は未実装。弱点克服には苦手キー分析の方が
  効くと判断して後回しにした
