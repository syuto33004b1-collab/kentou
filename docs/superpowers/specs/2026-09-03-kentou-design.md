# 鍵闘 KENTOU — 設計書

- 日付: 2026-09-03
- 種別: 新規プロジェクト設計（architectural）
- 公開先: https://syuto33004b1-collab.github.io/kentou/

## 1. 目的

タイピング練習を「格ゲーの1試合」として成立させる。ただ速く打つのではなく、
**1打ごとの手応え**と**お題を打ち切った瞬間の爆発**を分けて設計することで、
爽快感と打撃感を作る。

## 2. 確定した方針

| 項目 | 決定 |
|---|---|
| お題の言語 | 日本語ローマ字入力（漢字表示＋かな読み＋ローマ字ガイド） |
| コアループ | CPU対戦・体力バー式（先にHP0にした方がKO） |
| 素材 | 外部素材ゼロ。キャラはSVG、エフェクトはCanvas、SEはWeb Audio合成 |
| 技術スタック | 素の静的サイト（HTML/CSS/ESモジュール）。ビルド工程なし |
| デプロイ | GitHub Pages「main ブランチ / (root)」。Actionsワークフローなし |

### 却下した案

- **単一HTMLファイル**: 最小だが1500行を超えると保守不能。
- **Vite + TypeScript + Actions**: 型安全と拡張性は上だが、この規模ではビルド
  パイプライン・node_modules・CI設定のコストが上回る。ビルドがないことで
  「pushした瞬間に公開版が変わる」= デプロイのデバッグがゼロになる利点を取った。

## 3. 画面構成とゲームフロー

```
TITLE ──[任意キー]──> FIGHT ──[HPが0]──> ROUND_END ──[R]──> FIGHT
```

FIGHT画面（上から）:

- **上段**: 左右に体力バー（PLAYER / CPU）、中央にコンボカウンタと残り時間ゲージ
- **中段**: 対戦キャラのSVGシルエット2体。ヒットでノックバック、被弾で赤フラッシュ
- **下段（主役）**: お題表示。漢字 → かな読み → ローマ字ガイドの3層。
  ローマ字は**打った分が光って確定 / 次の1文字がカーソル強調 / 残りは減光**
- 全面に重ねたオーバーレイCanvas（パーティクル用）

## 4. 入力判定エンジン（`src/romaji.js`）

本プロジェクト唯一の非自明ロジック。かな列を**受理オートマトン**として扱う。

### トークン化

1. 拗音の2文字（`きゃ` `しゅ` `じょ` など）を最長一致で1トークンにする
2. `っ`（促音）は**次のトークンに融合**し、綴り集合を生成する
   - 子音重ね形: 次トークンの各綴り `s` について `s[0] + s`（`っし` → `sshi`, `ssi`）
   - 明示形: `xtu`/`ltu`/`xtsu`/`ltsu` + 次トークンの各綴り
3. `ん` は後続文脈で綴り集合が変わる
   - 後続が母音・`n`・`y`始まり、または語末 → `nn` / `n'` / `xn`
   - それ以外 → 上記 ＋ 単独 `n`
4. それ以外のかなは五十音テーブルを引く。テーブルは訓令式・ヘボン式・
   一般的な変則綴りを併記（`し` → `shi`/`si`/`ci`、`つ` → `tsu`/`tu`、
   `じゃ` → `ja`/`jya`/`zya`）

### 判定

状態は `{ tokenIndex, buffer }` のみ。1打ごとに:

1. 現トークンの綴り集合から `buffer + 入力文字` を接頭辞に持つ候補を絞る
2. 候補が空 → **ミスタイプ**（状態は動かさない）
3. 候補に `buffer + 入力文字` と完全一致するものがあれば → トークン確定、次へ

**エッジケースの明示的対応**: `ん` を単独 `n` で確定した直後に、
ユーザーがもう一度 `n` を打った場合（`nn` の打ち癖）はミスにせず飲み込む。
実際のIMEはこの入力を受理するため、ここで不当なミス判定を出さない。

### 割り切り

日本語IMEの完全互換は狙わない。主要な綴りをテーブルで持ち、テストで固定する。

## 5. 戦闘ロジック（`src/game.js`）

- HP: PLAYER 100 / CPU 100
- **お題を1つ打ち切る = 1回の攻撃**
  `ダメージ = 基礎値 × 速度補正(KPM) × コンボ倍率 × ノーミス補正`
- **CPUの攻撃**: お題ごとの制限時間 = `お題の打鍵数 × CPUの1打あたり秒数`。
  時間切れでプレイヤーが被弾
- **ミスタイプ**: コンボリセット ＋ 小ダメージ
- **難易度はCPUのKPMという数値ひとつだけ**。AIは作らない

## 6. 演出レイヤー（`src/fx.js` / `src/sound.js`）

打鍵1回の手応えと、打ち切った瞬間の爆発を**別の強さ**で設計する。

### 1打ごと（軽い手応え）

短い高音クリック（square波・decay 30ms）＋ 確定文字が白く光ってスケールアップ
＋ 2〜3px / 40ms の極短シェイク

### お題完打 = ヒット（爆発）

`ヒットストップ80ms（全アニメ停止）` → `画面フラッシュ` →
`Canvasパーティクル40発放射` → `打撃音（sineのピッチダウン＋ノイズバースト）` →
`ダメージ数値が跳ねて浮上` → `相手キャラがノックバック＋赤フラッシュ` →
`体力バーが削れる（削れた分が遅れて追いつくチップダメージ表示）`

### コンボ

`5 COMBO!` がスケールインしてブレる。伸びるほど**SEのピッチが上がり**、
パーティクル色が 白 → 黄 → 橙 → 赤紫 に変化する。

### ミス

赤フラッシュ ＋ 低いブザー ＋ お題文字が赤く震える ＋ `BREAK` 表示

### K.O.

スロー0.3倍 → 暗転 → 巨大な `K.O.` が叩きつけられる ＋ 全画面激震 ＋ 低音の轟音

### 音の初期化

SEは全てWeb Audio APIの合成音（音源ファイルなし・ライセンス問題なし）。
AudioContextは**最初のキー入力で resume** する（ブラウザのautoplay policy対策）。

## 7. アクセシビリティ（削減対象外）

- `prefers-reduced-motion: reduce` でシェイク・フラッシュ・パーティクルを停止。
  ヒットストップとダメージ数値は残す（ゲーム性を保つため）
- 光感受性対策: フラッシュは全画面白100%にせず不透明度0.35程度まで。
  3Hzを超える連続フラッシュは出さない
- 音のON/OFFトグルを常設

## 8. お題データ（`src/words.js`）

格ゲー由来の語彙で世界観を作る。3系統:

- **技名系**: 波動拳、昇龍拳、竜巻旋風脚、瞬獄殺 …
- **格ゲー用語系**: 確定反撃、目押し、暴れ潰し、起き攻め、差し返し …
- **実況セリフ系**: まだ終わらんよ、完全に読み切った、圧倒的 …

かな長で3段階（短／中／長）に分け、コンボが伸びるほど長いお題が出る。

## 10. 検証方針

- **自動テスト**: `src/romaji.test.js` のみ。nodeの `assert` だけを使い、
  フレームワークは入れない。検証項目は拗音の複数綴り、`っ` の子音重ね、
  `ん` の `n`/`nn`/`xn`、`si` と `shi` の分岐後の状態遷移、
  単独 `n` 確定後の追加 `n` の飲み込み。
  実行: `node src/romaji.test.js`
- **演出とレイアウト**: 自動テストの対象にしない。実機で動かして
  スクリーンショットで確認する。

## 11. デプロイ

1. `gh repo create kentou --public`
2. main に push
3. GitHub Pages を「Deploy from a branch: main / (root)」に設定

ビルド工程がないため Actions ワークフローは作らない。
