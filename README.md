# 鍵闘 KENTOU

格ゲー風のタイピング練習サイト。日本語のお題をローマ字で打ち切るたびに、
一撃がCPUに入る。打鍵1回の手応えと、打ち切った瞬間の爆発を別に設計している。

**▶ https://syuto33004b1-collab.github.io/kentou/**

## 遊び方

日本語入力（IME）はOFF、半角英数にしてから始める。ONのままだと画面が警告を出す。

| キー | モード | CPUの速度 |
|---|---|---|
| `0` | 診断 / CALIBRATE | 10秒の実測。おすすめモードを出す |
| `1` | 見習い / ROOKIE | 110 KPM |
| `2` | 闘士 / FIGHTER | 190 KPM |
| `3` | 鬼 / DEMON | 290 KPM |
| `4` | 修練 / TRAINING | 時間制限なし |

はじめてなら `0` の診断から。10秒の短文で実測KPMを出し、互角に戦えるモードを
提案する。実測値は保存され、次からタイトルでおすすめが光る。

CPUの速度は表の値に固定ではなく、**追い詰めるほど速くなる**（基準の0.82倍→1.28倍）。
序盤は緩く、終盤は締まるので、どのモードでも途中で必ず互角の帯を通る。
現在の実効KPMは残り時間ゲージの下に出る。

- **打ち切る＝攻撃**。速く・ノーミス・コンボが乗るほど威力が上がる
- **時間切れ＝被弾**。お題ごとの制限時間を切らすとCPUの攻撃が入る
- **ミス＝よろけ**。コンボが半減し、小ダメージを受ける
- **時間切れの被弾は打てていた分だけ軽い**。あと一歩で落とした被弾は、
  手つかずで落とした場合の半分以下になる
- 先に体力を0にした方がKO。`R` でもう一戦、`V` でリプレイ、`Esc` でモード選択に戻る
- 画面から離れる（タブ切り替え・ウィンドウのフォーカス外れ）と自動でポーズする

### 攻撃の階級

ダメージに応じて、ヒットストップ・打撃音・ノックバック距離・パーティクル量が
弱／中／強／必殺の4段で変わる。長いお題、ノーミス、高コンボが重なると必殺級になる。

- **COUNTER** — 残り時間が15%を切ってからの完打。ダメージ1.4倍
- 残り1〜2文字でキャラが踏み込む（予兆）。当たる前の溜めが打撃感の本体

### 修練モード

時間制限もCPUの攻撃もない。カテゴリ（技名／格ゲー用語／実況セリフ）と
長さ（短文／中文／長文）を選んで、苦手なところだけ反復できる。
打鍵数・正確率・KPMは打つたびに更新される。

### 自作のお題

タイトルの「自作のお題」から、自分の練習したい語を入れられる。1行に1つ、
`漢字,かな` か `かな` だけ。`#` の行は無視する。保存時に1行ずつローマ字化を
検証し、打てない綴りは行番号と理由を出して弾く。

出題は「既定のみ／既定＋自作／自作のみ」で切り替えられる。修練モードでは
`自作` がカテゴリとして選べる。

### 記録とリプレイ

結果画面に出るもの:

- **ミスが多いキー**のワースト5（まだミスが無ければ**打つのが遅いキー**）
- 前回比、自己ベスト、通算成績
- **お題ごとの所要時間**。バーは制限時間に対する割合で、赤は落としたお題。
  どこで詰まったかが一目で分かる
- `V` で**リプレイ**。その試合の打鍵を記録した間隔どおりに再生する

すべてブラウザの localStorage に入るだけで、どこにも送信しない。

## 入力について

訓令式・ヘボン式のどちらでも受理する。タイトル画面の「ローマ字の受理ルール」に
表がある。

- `し` → `shi` / `si` / `ci`
- `つ` → `tsu` / `tu`
- `じゃ` → `ja` / `jya` / `zya`
- `っ` → 子音重ね（`せっか` → `sekka`）または `xtu` / `ltu`
- `ん` → 後続が子音なら `n` 単独でよい。母音・な行・や行の前と語末は `nn` / `n'` / `xn`
- `ん` を `n` 単独で確定した直後の追加 `n` は、IMEと同じく飲み込む

## 音について

打撃音・被弾音・KO音・ミス音・1打ごとのクリックは、すべて Web Audio API の合成音。
音源ファイルは持たない。薄い音にならないよう1発を4層で作っている。

| 層 | 役割 |
|---|---|
| トランジェント | 高域ノイズの極短バースト。当たった瞬間のクラック |
| ボディ | サチュレーション（`WaveShaperNode`）を通した中低域。倍音が出て「ドン」になる |
| サブ | 30〜60Hz の正弦波。重厚感の正体。歪ませず深く伸ばす |
| テール | ローパスを通したノイズの長い減衰。空間と破片 |

マスターにコンプ（`DynamicsCompressorNode`）を挟んで層を糊付けしている。
ただし強く掛けると弱／中／強／必殺の差が潰れるので、糊付けだけに留めた
（実測でランク間 4.3dB の差を確保）。

アナウンサーボイス（`ROUND 1` / `FIGHT!` / `COUNTER!` / `SUPER!` / `K.O.` /
`YOU LOSE`）だけは合成では作れないので、`audio/` に mp3 として置いている。
6本で合計30KB弱。取得や再生に失敗しても合成音だけでゲームは成立する。

**クレジット**: `audio/*.mp3` は [ElevenLabs](https://elevenlabs.io) で生成した。
無料プランで生成しているため帰属表示が必要で、タイトル画面と本ファイルに明記している。

## 構成

ビルド工程なし。素のHTML/CSS/ESモジュールだけで動く。外部ライブラリはゼロ。
キャラクターはSVG、エフェクトはCanvas、効果音はWeb Audio APIの合成音。
外部素材はアナウンサーボイスの mp3 6本だけ。

```
index.html
style.css
src/romaji.js       かな列→ローマ字入力の受理オートマトン
src/battle.js       戦闘の数値計算（ダメージ・COUNTER・階級・KPMランプ・モード推奨）
src/words.js        お題データと自作お題のパース・検証
src/stats.js        打鍵記録と苦手キー分析
src/store.js        localStorage の薄いラッパ（例外を必ず飲む）
src/screens.js      オーバーレイのHTMLを組む純関数
src/fx.js           Canvasパーティクル・画面シェイク・ヒットストップ
src/sound.js        Web Audio APIによる合成SE（4層 + マスターコンプ）
src/voice.js        アナウンサーボイスの読み込みと再生
src/game.js         状態機械と画面制御
audio/*.mp3         アナウンサーボイス6本（ElevenLabs生成）
```

`romaji.js` / `battle.js` / `stats.js` / `words.js` / `screens.js` / `store.js` は
DOM を触らないので、ブラウザなしで検証できる。`game.js` はそれらを画面と音に繋ぐだけ。

## 開発

```bash
python -m http.server 5173
```

`http://127.0.0.1:5173/` を開く（ESモジュールを使うので `file://` では動かない）。

テストは DOM を持たないモジュールに置いている。フレームワークは使わず node の
`assert` だけ。

```bash
node src/romaji.test.js && node src/battle.test.js && node src/words.test.js && node src/stats.test.js
```

- `romaji.test.js` — 拗音・促音・撥音の綴り分岐と、全108お題が表示ガイドどおりに
  打ち切れること
- `battle.test.js` — COUNTERの閾値と倍率、速度補正のクランプ、コンボ上限、
  「一戦で弱・中・強・必殺が順に出る」こと、KPMランプの単調性、
  被弾が進捗で軽くなること、実測KPMからのモード推奨
- `words.test.js` — 自作お題のパースと検証（打てない綴り・重複・上限）、
  出題ソースの切り替え、カテゴリ×長さの全組み合わせが引けること
- `stats.test.js` — 苦手キーの並び順、異常な打鍵間隔の除外、自己ベストの更新条件

演出とレイアウトは自動テストの対象にしていない。実機で動かして確認する。

## アクセシビリティ

- `prefers-reduced-motion: reduce` でシェイク・フラッシュ・パーティクル・予兆を停止する。
  ヒットストップとダメージ数値は残すので、ゲームとしての手応えは変わらない
- 全画面フラッシュは不透明度0.35までに制限し、点滅を繰り返さない
- 音のON/OFFトグルを常設
- モードはクリック／タップでも選べる。ただし本体は物理キーボードが必要なので、
  タッチ環境ではその旨を表示する

設計は `docs/superpowers/specs/` にある。
